# v0.36 7단계 — 시드 저장 · 다른 기기로 옮기기

기획 문서 §4와 확정사항 기록의 「저장 — A안」을 반영했습니다. 브랜치 `claude/v0.36-seed`, 기준은 6단계(`claude/v0.36-formation`).

## 시드
- 시드는 **저장의 이름**입니다. 형식은 `EMBR-XXXX`, 헷갈리는 I · O · 0 · 1을 뺀 32글자를 씁니다(`dist/seed.js`).
- 원정 난수는 **시드 + 원정 회차**로 만듭니다(`expeditionSeed(seed, run)`). 같은 시드의 같은 회차는 같은 지도·같은 난수로 시작합니다.
- 시드·원정 회차(`runs`)·클리어 횟수(`clears`)는 `s.collection`에 있어 원정이 끝나도 남습니다.

## 타이틀
- 기록이 없을 때: 「원정 시작」 → 시드 입력 창. 빈칸이면 무작위 시드로 시작합니다.
- 기록이 있을 때: 「이어하기 (시드)」 / 「다른 시드로 시작」 / 「저장 파일 불러오기」 / 「메뉴」.
- 시드를 적었을 때
  - 이 기기에 그 시드의 기록이 있으면 요약(마지막 플레이 · 클리어 · 원정 회차)을 보여 주고 **이어받을지** 묻습니다.
  - 없으면 "이 시드의 기록이 없습니다. 저장 파일을 불러올까요?" → 「저장 파일 불러오기」「코드 붙여넣기」「이 시드로 새로 시작」.
- 「다른 시드로 시작」은 지금 기록을 지우지 않습니다. 시드마다 저장 칸이 따로 있습니다.

## 저장 칸과 자동 저장
- 저장 칸은 `teyvat-embers-save:<시드>`, 마지막으로 쓴 시드는 `teyvat-embers-last-seed`입니다(`saveStore`).
- 행동 하나가 끝날 때마다 저장합니다. 노드 이동 · 전투 전 · 보상 후가 모두 여기에 들어갑니다.
- v0.35까지의 단일 저장 칸(`teyvat-embers-v1`)은 처음 한 번 무작위 시드를 붙여 새 칸으로 옮깁니다. 옛 칸은 지우지 않습니다.

## 다른 기기로 옮기기
- 메뉴 → **저장**(또는 환경설정 → 저장 · 안내): 시드 표시 · 「시드 복사」 · 「저장 파일 내보내기」 · 「코드 복사」 · 「저장 파일 불러오기」 · 「코드 붙여넣기」.
- 저장 파일은 `<시드>.embers`(JSON)입니다. `format: 1`, 시드, 저장 시각, 클리어·회차, 설정, 진행 상태(로비 누적 기록 + 진행 중인 원정)를 담습니다.
- 코드는 같은 내용을 한 줄로 만든 것입니다. 압축을 쓸 수 있는 브라우저에서는 `EMBR2:`(압축), 아니면 `EMBR1:`입니다. 검사값이 들어 있어 잘린 코드는 알아챕니다. 원정 초반 기준 약 4천 자입니다.
- 불러올 때는 **읽기 → 비교 → 확인** 순서입니다.
  - 읽지 못하면 이유를 알리고 끝냅니다(손상 / 잔불 파일이 아님 / 더 새 버전의 파일 / 진행 기록을 읽을 수 없음 / 시드가 틀림). 이 기기의 기록은 건드리지 않습니다.
  - 입력한 시드와 파일의 시드가 다르면 경고합니다.
  - 같은 시드의 기록이 이 기기에 있으면 양쪽의 마지막 플레이 일시 · 클리어 횟수 · 원정 회차를 나란히 보여 주고 「덮어쓰기」를 눌러야 바뀝니다.
- v0.35까지 내보낸 JSON 파일도 읽습니다(시드가 없으면 새로 붙입니다).
- 클라우드 저장은 넣지 않았습니다.

## 파일
- `dist/seed.js` — 시드 만들기 · 정리 · 숫자화. 다른 모듈을 불러오지 않습니다.
- `dist/save-seed.js` — `packSave`, `parseSave`, `saveCode`, `saveStore`, `saveSummary`.
- `dist/app.js` — 시드 입력 · 이어받기 · 불러오기 확인 창, `save()`.
- `dist/title-screen.js`, `dist/menu-ui.js` — 타이틀 선택지, 메뉴의 저장.
